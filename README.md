# Pinecone Hybrid RAG (retrieval + metrics only)

A credential-free, TDD-driven retrieval demo that builds a **hybrid BM25 + Pinecone vector** retriever with doc-level ensemble fusion and reports P@5/R@5 with a ceiling/normalized view.

Scope: retrieval and metrics only. **No LLM generation**, no `ChatOpenAI`, no LCEL chain. Pinecone SDK is pinned to `pinecone==7.3.0` (legacy API). LangChain is imported lazily so the unit suite runs with zero keys.

## Prerequisites

- Python 3.12
- [`uv`](https://docs.astral.sh/uv/)
- A Pinecone account and index (only for live `init_index` / `ingest` / `evaluate` without `--offline`)
- An OpenAI API key (only for live embedding calls)

## Install

```bash
uv venv --python 3.12 .venv
# Windows
uv pip install --python .venv\Scripts\python.exe -r requirements.txt
# macOS/Linux
# uv pip install --python .venv/bin/python -r requirements.txt
```

## Configure

```bash
# Copy the example and fill your keys
Copy-Item .env.example .env  # Windows PowerShell
# cp .env.example .env      # macOS/Linux
```

Required values in `.env`: `PINECONE_API_KEY`, `OPENAI_API_KEY`, `INDEX_NAME`. Defaults: `PINECONE_NAMESPACE=rag-docs`, `ENSEMBLE_BM25_WEIGHT=0.4`, `ENSEMBLE_VECTOR_WEIGHT=0.6`. If a required key is missing, every CLI exits **code 2** with a remediation message pointing to `.env.example` and `uv run pytest -q`.

## Initialize the index

```bash
uv run python scripts/init_index.py
```

Creates/verifies the serverless index with `dimension=1536`, `metric=cosine`. If the index already exists with a different dimension or metric the script **does not** delete or recreate it (it raises `IndexConfigMismatchError`).

## Ingest the corpus

```bash
uv run python scripts/ingest.py
```

Loads `data/corpus/*.md`, chunks with `RecursiveCharacterTextSplitter` + `tiktoken` (`cl100k_base`, 600/80), builds the fixed metadata schema (9 fields + `text`), asserts embedding dimensions before upsert, and writes to Pinecone via `PineconeVectorStore` (`text_key="text"`, namespace from config). Vectors are upserted in batches of 32 and `chunk_id` is used as the vector id.

## Evaluate

```bash
# Live evaluation (needs keys + ingested index) — writes artifacts/last_eval.json
uv run python evaluate.py

# Regenerate the committed artifact (no keys required) — scores the frozen
# calibration worked example in data/calibration_set.json deterministically
uv run python evaluate.py --calibration

# Offline reprint (no keys required) — prints the committed artifact and its
# provenance (calibration demonstration vs live run)
uv run python evaluate.py --offline
```

The report prints P@5/R@5, the structural ceiling, normalized precision, and a three-row ablation (`vector`, `bm25`, `hybrid`). The committed `artifacts/last_eval.json` is the frozen calibration demonstration (P@5=0.36, R@5=0.833333, ceiling=0.44, normalized=0.818182), regenerated by `--calibration`; a live run overwrites it with real retrieval results.

## Run tests (credential-free)

```bash
uv run pytest -q
```

All unit tests use fakes; `@pytest.mark.integration` tests auto-skip unless both `PINECONE_API_KEY` and `OPENAI_API_KEY` are set.

## Notes on metrics

- **Fixed denominator:** `precision_at_k` uses `k` even when fewer than `k` documents are retrieved (thin retrieval is penalized).
- **Deduplication:** retrieved ids are deduplicated preserving first occurrence before truncation.
- **Redundancy:** when every question has exactly one relevant document, `R@k = k · P@k`. The committed Golden Set requires **≥2** relevant documents per question.
- **Ceiling:** `ceiling = (1/N) · Σ min(m_q, k)/k` captures the structural maximum; `normalized_precision = P@k / ceiling` (0 when unreachable).
- **Aggregation:** macro-averaged over questions (each question weighted equally).

## Doc-level fusion tradeoff

`RAGSystem` builds an `EnsembleRetriever` with `weights=[0.4, 0.6]` (BM25 : vector), `id_key="document_id"`, and `k=20` per retriever. Because the ensemble returns the union of candidates, **`retrieve()` defensively deduplicates by `document_id` (preserving fused order) and slices to `[:5]` itself**. Single-mode runs (`vector`/`bm25`) use one retriever directly (no degenerate `[1.0]` ensemble).

## BM25 hydration & cache

On initialization the BM25 corpus is hydrated from Pinecone via `index.list(namespace=...)` followed by batched `index.fetch` (`≤1000` ids per call). The namespace is **always passed explicitly** (never `None`). Results are cached at `artifacts/bm25_corpus.json` (gitignored) keyed by `(index_name, namespace, pipeline_version, ceil(vector_count/1000))` plus the exact `vector_count`. If Pinecone is unavailable or the namespace is empty, it falls back to re-chunking `data/corpus/`. If both fail, `HydrationError` is raised naming the cache path and remediation. `artifacts/last_eval.json` **is committed** so `--offline` works without credentials.

## Scale notes

Hydration does O(N) id listing + one fetch per 1000 ids (returning full 1536-dim vectors) — correct for roughly **10⁴–10⁵ chunks**. Beyond that you would need Pinecone native full-text search or an external BM25 service.

## Troubleshooting

| Issue | Fix |
|---|---|
| Exit code 2 on a CLI | Copy `.env.example` to `.env` and set the listed keys. Run `uv run pytest -q` to verify the credential-free path. |
| Wrong namespace / empty results | Ensure `PINECONE_NAMESPACE` matches the namespace used by `ingest.py`. The default is `rag-docs` (never the empty/default namespace). The vector store uses `text_key="text"`. |
| Stale BM25 cache | Delete `artifacts/bm25_corpus.json` or bump `PIPELINE_VERSION` to force re-hydration. |
| Index dimension/metric mismatch | `init_index` refuses to recreate the index. Either use a compatible index or recreate it manually in the Pinecone console. |
| SDK pin rationale | The project uses `pinecone==7.3.0` with the legacy surface (`Pinecone`, `pc.create_index` + `ServerlessSpec`, `pc.Index`). `langchain-pinecone==0.2.13` is pinned for compatibility. |
